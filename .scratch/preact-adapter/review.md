# Review-fix notes

## Finding 1: client-only render leaves host empty -- DONE
- Fixed in the adapter (not core): `src/preact.browser.ts` keeps one
  `dangerouslySetInnerHTML` object per component instance (`useRef` from
  `preact/hooks`). Its `__html` getter returns `renderParts(own, {attrs})`
  html until the host's ref fires (host committed), then a fixed value.
  Preact never reads `__html` while hydrating (diff/index.js
  `!isHydrating && ...`), so it is read before commit only on a
  client-only mount, and innerHTML is set before the element connects.
- Test fixture in test/preact-browser.ts no longer renders in setup; it
  uses refs (`r.one`). Client-only + events tests failed red before.
- Size: browser adapter 443 -> 564 B; limit raised 450 -> 600 B.
- Docs: README Preact section, ADR-010 decision/consequences, AGENTS.md.
- Client-only mount requires render support registered (full variant
  via the build transform); otherwise renderParts throws naming subpath.

## Finding 2: declared props lost during hydrate -- DONE
- Host `ref` is a fresh closure per render (Preact calls it on every
  commit); it marks the instance live and assigns each non-function
  declared prop where `el[k] !== v`. Functions are skipped since Preact
  sets functions while hydrating and the accessor treats them as signals.
- Test: `hydrate assigns a prop-only declared prop` (p.prop list) in
  test/preact-browser.ts; red before, green after.
- Size 585 B (limit 600 B). README + ADR-010 updated.

## Finding 3: renderHost not byte-identical on same-name extra attr -- DONE
- Read as "unrecorded behavior change": kept the new (dedupe) behavior,
  since parts.attrs is a record and the parsed DOM is unchanged.
- Pinned with `render: a declared prop wins over an extra attr of its
  name` in test/ssr.ts (passes on current code; there was no red step
  because the code was not wrong, only undocumented).
- Recorded in ADR-010 Consequences. CHANGELOG.md is regenerated by
  auto-changelog in the `version` script, so instead of a hand entry the
  commit carries a `BREAKING CHANGE:` footer (matches
  `--breaking-pattern`), which puts it in the 0.1.0 changelog.
